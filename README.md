# 潘小兜老卤 · 单店预约点餐与会员运营

微信原生小程序 + Node.js/TypeScript/Koa + MySQL 8 + 微信云托管。

面向临安周边居民，支持按日期批次预订、店主自送与到店自提。当前经营规则为每天16:30一批、16:00截单、可预约次日；累计有效现金货款满68元付款后晋升会员，下一单享逐商品会员价；推荐红包仅抵货款，在好友完成订单后结算。可通过掌柜后台调整运营参数。

## 当前实现

- 服务端以分计算金额，叠加抵扣不超过货款，不抵配送费；结算与下单再次核价。
- 微信支付 API v3 下单、响应/通知验签、通知解密、主动查单、整单退款及结果同步（含掌柜发起的履约后售后退款）；客户端不再能声明支付成功。
- 下单请求幂等；按日期批次预占接单名额、库存与积分；取消或超时关单释放；支付与关单竞争时核对渠道结果。
- 所有订单及分页查询，区分已取消、退款处理中、已退款；配送和自提分别发车、备好与核销。
- 掌柜账号由部署环境白名单授权，公开配置不返回口令；后台资产变动与审计原子提交，调整请求可安全重试。
- 营业设置可维护自提地址、联系人、电话与付款时限；读取成功后才能保存，多设备修改冲突时保留填写并提示重新核对。顾客可复制门店地址，历史自提订单使用下单时保存的地址。
- 会员门槛、退出后不自动入会、推荐人资格、完成后赠积分和推荐奖励；积分红包流水可查；售后退款冲回已发奖励，已用部分从后续同类奖励抵回，不扣现金。
- 手机工作台按日期、状态、自送/自提筛选订单，显示批次接单容量、汇总待备餐份数、维护菜品与每批剩余份数；全部日期待办、前台新单/售后检查、往日未取餐提醒与联系顾客、掌柜核实送达留痕；支持再来一单。
- 会员和推荐好友按游标分页，统计真实总数；按订单提交售后、查看处理进度，掌柜集中接单与回复。
- 会员专属邀请海报：云托管制码、画布预览与相册保存、扫码及热启动邀请码解析；需配置云调用并完成真实扫码验收。
- 掌柜经营日报按北京时间区分支付/退款入账日与预约履约日，提供明细分页、菜品份数和积分红包变动；顾客实付/实退缺失时明确提示待核对，不猜测现金收入。

**代码实现不代表已完成线上验收。2026-11-19已完成生产增量迁移和后端部署，当前pandou-004（003镜像及用户指定掌柜配置），云网关健康200/UP，接单关闭、业务公网关闭。当前控制台微信已获掌柜授权；商户文件尚待准备，微信真机付款退款、云端海报及相册/扫码仍未验收。** 完整进度见 [上线进度](docs/线上使用完善进度.md)。 新增“个人信息与账号”入口，可更正资料、清除本机收货资料、提交信息处理申请并查看掌柜回复；回复本身不会自动注销账号或删除历史交易。

## 开发与检查

**测试号本机联调已配置**：在 `server` 目录执行 `npm run local:start`，后端使用 `http://127.0.0.1:18080`，数据库为独立持久本机库。开发者工具打开本项目根目录并编译；会员页可切换测试新客、会员和掌柜，正金额支付可选模拟成功、失败或取消。不会真实扣款。启停、测试账户、流程及限制见[本机联调指南](docs/本机联调指南.md)。

需要 Node.js 22+、MySQL 8。

```sh
cd server
npm ci
npm test
```

当前目标 AppID `wx8e2380dec308d5de` 已由用户确认为小程序测试号。项目根目录和小程序目录的导入配置已同步；`miniprogram/config/runtime.js` 仅 `develop` 开启本机开发身份，连接 `http://127.0.0.1:18080`，由独立本机库及显式模拟支付支持联调。`trial`、`release` 的云环境仍留空，空目标或未知版本停止请求，不回退到本机或原云环境。此前云平台拒绝测试号资源复用的提示不能证明存在两个不同的正式经营主体。原环境 `prod-d8gf0ab0a1eeb1899` / `pandou` 的已部署参数和用户数据保留；真实收款与正式发布仍须取得正式小程序账号、核对环境关联/商户绑定，并按新身份重新授权及处理数据迁移。

本地联调显式设置服务端 `NODE_ENV=development`、`ALLOW_DEV_AUTH=true`，并仅在 `develop` 配置中启用 `allowLocalDev`；默认地址为 `http://127.0.0.1:8080`。开发模式会优先请求该本机地址，即使配有云环境也不会混用。联调身份头是 `x-dev-openid`，query openid 不受支持；体验和正式版不能开启本地身份模式。

## 数据库与部署

1. 在独立测试库验证后，首次空库使用 `init.sql`；已有数据环境不得重新导入这个重建脚本。
2. 配置 `server/.env.example` 中的数据库环境变量，以迁移账号执行 `npm run migrate`。迁移是增量式，并记录每一步的校验和，可在中断后恢复；升级前应有可恢复的数据库备份。
3. 通过密钥挂载或受保护的环境变量配置微信支付参数、掌柜 OpenID 白名单，详见 [上线运行与验收](docs/上线运行与验收.md)。口令登录已移除。
4. Docker 在8080端口以非root账号运行。营业环境至少保留1实例，以便持续处理未付款超时、支付结果和退款补偿；云托管规格与费用以控制台为准。
5. 普通顾客和掌柜接口只经微信云托管可信网关访问，业务服务关闭公网。若平台无法按路径限制，则另部署 `SERVICE_MODE=callbacks` 的公网回调服务，仅开放两条POST通知和GET/HEAD健康检查；不识别来访身份、不运行后台轮询。回调服务尚待商户配置后部署。
6. 小程序使用项目根目录导入微信开发者工具。上线前核对 AppID、云环境、服务名、隐私授权、合法图片域名及真实商品信息。

运行 `npm run preflight` 只读检查部署配置与数据库迁移校验和；可用 `npm run preflight -- --config-only` 先查配置。检查不会打印密钥值，也不能替代公网身份边界与真实资金验收。`npm run release` 生成带SHA256清单的代码发布包，输出到根目录 `.runtime/releases/`。

旧版本没有真实支付凭据的订单会被迁移标记为 `LEGACY`，不自动假定其已经收款，需掌柜逐笔核对后处理。原账户余额及历史数据不会被自动清零。

邀请海报需在云托管开启开放接口服务，授权 `/wxa/getwxacodeunlimit`，重新构建后设置 `WECHAT_OPENAPI_ENABLED=true`；默认关闭，不接收或向前端返回令牌和AppSecret。配置步骤见上线运行与验收。

每批接单上限通过掌柜后台 `BATCH_MAX_ORDERS` 配置，0表示不限，最大9999；未付款也占名额，备好或发出后的订单仍计入本批工作量。

## 独立 MySQL 集成验证

提供临时 MySQL 配置与集成用例，测试只会创建并删除随机命名的 `pandou_test_*` 数据库：

```sh
cd server
docker compose -f compose.test.yml up -d --wait
TEST_MYSQL_HOST=127.0.0.1 TEST_MYSQL_PORT=33316 TEST_MYSQL_PASSWORD=pandou-test-only npm run test:integration
docker compose -f compose.test.yml down
```

该用例验证真实 SQL、重复迁移、并发争抢末份、零元订单、重复下单、退款和资产库存返还，以及死锁恢复、后台审计故障回滚、资产调整幂等、列表分页、售后权限、完成后退款奖励冲正、已用奖励抵回及退会清零不重复扣回。另覆盖商品有库存时争抢批次名额、名额回滚与释放、图片登记、个人信息申请、日报跨日退款/一致快照/实付缺失，以及有历史数据的001至009分阶段迁移。它不接触微信真实资金；真实支付验收必须另做。
