# 上线运行与验收

此文是当前目标的交付与验收依据，不表示下列线上步骤已经执行。

## 已确认经营规则

- 每天16:30一个批次，初始截单时间16:00，可预约次日；日期与批次由服务端校验。
- 累计有效现金货款满68元，付款后晋级会员，下一单按每道菜独立会员价购买。
- 有效货款不含配送费及各类优惠，现金付款按微信返回的实际付款金额计；退款退回对应累计消费，自动晋级会员不再达标时撤销资格。
- 普通积分在订单完成后发放，每满1元有效货款赠1分；每单100分抵5元，货款不足5元不消耗该次积分。
- 推荐人须为有效会员，新客首次下单前可绑定一次；单层奖励，好友订单完成后按有效货款的3%到账，不能提现。
- 红包初始最多抵货款50%，与普通积分叠加不能超过货款，也不能抵配送费。
- 退出会员须先处理完进行中订单，红包清零、普通积分保留，之后不自动再次晋级；免费模式可主动申请或由掌柜重新开通。

## 环境与密钥

通过云托管环境变量/密钥挂载配置，勿将密钥放入小程序或提交仓库：

| 参数 | 用途 |
| --- | --- |
| `MYSQL_ADDRESS` 或 `MYSQL_HOST`/`MYSQL_PORT` | 数据库地址 |
| `MYSQL_USERNAME` 或 `MYSQL_USER`、`MYSQL_PASSWORD`、`MYSQL_DATABASE` | 数据库凭据与库名 |
| `ADMIN_OPENIDS` | 逗号分隔的受控掌柜微信OpenID白名单；更改后重新部署生效 |
| `NODE_ENV=production`、`ALLOW_DEV_AUTH=false` | 生产身份模式 |
| `SERVICE_MODE=app` 或 `callbacks` | 业务服务或独立公网回调服务；省略时为app，其他值拒绝启动 |
| `WECHAT_OPENAPI_ENABLED` | 默认false；完成云调用权限及侧车配置后设true，启用专属小程序码制码，无需新增AppSecret |
| `PRODUCT_IMAGE_UPLOAD_ENABLED` | 默认false；配置存储侧车及权限后启用掌柜实拍上传 |
| `PRODUCT_IMAGE_ENV_ID`、`PRODUCT_IMAGE_BUCKET`、`PRODUCT_IMAGE_REGION` | 对象存储环境、桶名和地域；不接收客户端覆盖 |
| `WECHAT_APP_ID` | 与商户绑定的小程序AppID，应与project.config.json一致 |
| `WECHATPAY_MCH_ID` | 普通商户号 |
| `WECHATPAY_CERT_SERIAL` | 商户API证书序列号，用于商户请求签名 |
| `WECHATPAY_PRIVATE_KEY_PATH` | 商户API证书私钥文件绝对路径 |
| `WECHATPAY_API_V3_KEY` | 32字节API v3密钥，用于通知解密 |
| `WECHATPAY_PUBLIC_KEY_ID`、`WECHATPAY_PUBLIC_KEY_PATH` | 微信支付公钥ID及对应公钥文件，用于平台响应和通知验签 |
| `WECHATPAY_PREVIOUS_KEY_ID`、`WECHATPAY_PREVIOUS_KEY_PATH` | 可选，轮换期间保留的上一验签密钥 |
| `WECHATPAY_NOTIFY_URL` | HTTPS公网支付回调地址 `/api/payment/notify` |
| `WECHATPAY_REFUND_NOTIFY_URL` | HTTPS公网退款回调地址 `/api/refund/notify` |

也支持不带 `_PATH` 的PEM环境变量，但推荐挂载文件；文件应允许容器node用户读取。回调域名必须真实可达，不携带查询参数。

服务端只信任网关注入的 `x-wx-openid`。**公网入口必须只放行两条回调路径，普通用户/管理接口不能通过可自定义此身份头的公网直连访问。** 应在云托管网关/负载均衡配置路由限制，并通过外部请求实际验证；不能仅依赖前端没有传该头。

若平台只能整体开启/关闭服务公网，采用两个服务部署同一代码包：业务服务 `pandou` 设置 `SERVICE_MODE=app` 并关闭公网，保留可信微信网关和内网访问；另建回调服务设置 `SERVICE_MODE=callbacks`，开启公网，将两条通知URL指向该服务。回调模式仅允许 `POST /api/payment/notify`、`POST /api/refund/notify` 和 `GET/HEAD /api/health`，在解析请求与识别身份前拒绝其他方法/路径，也不解析健康检查中的身份头。通知仍必须通过微信签名、交易身份和金额校验；模式本身不代替验签。回调实例不运行超时/退款轮询，由至少1个常驻业务实例处理。两边使用同一业务库并分别配置商户参数；不将业务服务的公网开关重新打开来接收通知。尚未配置商户参数时保持接单关闭，不能把健康检查通过作为支付可用的证明。

首次绑定掌柜：顾客账号访问小程序自动建档后，由有数据库权限的部署人员核对该人的账户，取真实OpenID写入 `ADMIN_OPENIDS`。不存在前端口令或自动提权接口。撤销白名单并重新部署后，客户端本地缓存不能保留权限。

## 数据升级与运行

1. 先备份现有库并验证恢复方式。`init.sql` 仅用于首次空库，会重建表，已有营业数据不得导入。
2. 本地隔离MySQL迁移验证已通过。用户已授权使用现有生产云环境联调；取得控制台访问并验证备份后，使用受控迁移账号执行 `npm run migrate`，检查每条迁移为APPLIED。应用运行账号不需要建表权限。
3. 在受控维护窗口暂停旧应用写入，完成迁移和新版本自检后恢复接单。将运行环境与小程序同步切换到新版本（含001至009全部迁移）；新前端不能搭配旧接口。旧 `server-deploy.zip` 未包含本轮实现，不可作为新版本发布包。
4. `/api/health` 验证数据库与新增核心表可读。支付参数、权限、回调路由仍须单独验收，健康检查不等于资金链路通过。
5. 营业环境保留至少1实例，每30秒尝试扫描超时订单与待退款订单；上一轮未结束时不重叠运行。两类队列分别按订单ID每轮最多20笔轮转，处理失败也推进扫描位置，到末尾后重新检查前面的未完成记录，避免前20笔持续异常堵住后续正常订单。进程内扫描位置重启后归零，订单本身仍在数据库；多实例通过数据库行锁和固定退款号协调，不以扫描位置认定已完成。
6. 建立容器错误告警，关注日志 `Order expiry retry required`、`Refund reconciliation failed` 和订单 `refund_error`；错误日志只记录请求号/订单号/错误类型，不包含密钥、地址和手机号。
7. 历史订单为LEGACY，旧系统的“已付款”无法证明真实收款。逐笔对照微信商户账单及线下收款记录，再决定退款、线下履约或归档；当前不会自动将它们重新结算或发奖。
8. 升级是增量式，恢复备份及回滚应用版本必须协调进行；旧代码会重新暴露模拟支付和口令授权问题，不应在开放营业时直接回滚运行。

在服务目录执行 `npm run preflight`，只读核对生产身份模式、掌柜白名单、数据库连接、支付参数、可读RSA密钥、HTTPS回调路径及每条迁移校验和。失败时退出码为1，只输出检查名称与通过状态，不输出秘密值；`npm run preflight -- --config-only` 可先查配置而不连接数据库。它不能证明公网路由隔离、商户绑定或真实资金成功，这些仍须实际验收。

`npm run release` 先构建，再以文件白名单生成 `.runtime/releases/<时间>/pandou-server-<时间>.zip`，包含迁移、自检和此运行说明；附压缩包SHA256及逐文件清单，不收录 `.env`、本地测试数据或密钥。发布前核对清单与目标环境；压缩包完整性检查不等于云构建成功。

## 邀请海报与云调用配置

1. 在现有云托管控制台的“云调用”中授权 `/wxa/getwxacodeunlimit`，开启“开放接口服务”。制码和商品图片存储使用该服务，支付仍走现有API v3链路。
2. 开启后重新构建服务版本，使新实例具有开放接口服务，再配置 `WECHAT_OPENAPI_ENABLED=true`。没有配置时保持false，好友分享仍可使用。
3. 代码按官方要求向容器内固定 `http://api.weixin.qq.com/wxa/getwxacodeunlimit` 调用，不传令牌，要求响应带 `x-openapi-seqid`；不要把这个HTTP调用改为用户提供的地址。无需让顾客端访问制码接口或配置AppSecret。
4. 正式码固定跳转 `pages/index/index`，发布前确认该页面已存在；体验/开发码按版本生成并在海报标注仅供联调，不用于公开推广。扫描体验/开发码的微信用户仍须有对应版本权限。
5. 用真实有效会员生成海报，核对自己的邀请码、预览、拒绝及允许相册权限、保存文件、另一微信扫码进入、首次下单前绑定、重复绑定拒绝、退出会员后旧码失效和好友履约后奖励。客户端“保存成功”必须对应微信保存完成。
6. 首次上线前核对小程序隐私保护指引中的相册写入能力说明。模板、画布布局及接口替身测试不能代替微信真机保存与扫码验收。

## 商品实拍上传与存储

1. 部署007迁移并配置 `PRODUCT_IMAGE_ENV_ID`、`PRODUCT_IMAGE_BUCKET`、`PRODUCT_IMAGE_REGION`；在云调用中授权 `/_/cos/getauth` 和 `/_/cos/metaid/encode`，启用开放接口服务后重新构建。设 `WECHAT_OPENAPI_ENABLED=true`、`PRODUCT_IMAGE_UPLOAD_ENABLED=true` 才开放上传。不需要新增永久COS密钥。
2. 商品图桶客户端规则为 `{"read":true,"write":false}`（控制台“所有用户可读”）。服务端始终有读写权限，所有上传经掌柜身份与审计校验；不要开放客户端上传来替代掌柜鉴权。若桶有其他私密用途，应单独规划权限后再调整。
3. `callContainer`请求上限为100KB。掌柜拍照/选图后从原图最多4档缩放压缩，编码前限制64KB，给Base64膨胀和请求封装预留空间；超过预算时先拒绝，不分配Base64或发出请求。服务端仍限制2MB输入，仅接受单张JPEG/PNG/WebP，限制1600万像素，纠正方向、移除元数据、缩至1600边长并重新编码JPEG。新照片上传失败时保留原封面与表单，重试沿用请求号，或明确放弃新照片；未完成上传时不能保存菜品。
4. 服务端从固定侧车取得短期凭据和 `x-cos-meta-fileid`，签名后向配置桶写入；获取凭据、元数据及写入共用18秒超时。每实例最多两路图片处理。凭据不返回客户端、不打印。图片接口管理员验证后才解析较大请求，其他接口保留256KB限制。
5. 保存永久 `cloud://` 标识，不保存临时访问网址；仅接受本系统READY登记图片。微信 `<image>` 使用该标识，所有版本须核对云环境关联与可读权限。历史HTTPS封面继续兼容。
6. 对象存储写入与MySQL不能跨系统回滚。图片登记和审计在同一数据库事务内，失败时不返回成功，重试使用同一确定路径；写入成功但数据库提交失败可留下未登记文件。禁止自动删除替换/归档照片，订单快照可能仍在引用。清理前须同时核对图片登记、现有商品和全部历史订单，并人工处理不确定的上传结果。
7. 真机验收拍照、相册/隐私授权拒绝、横竖图方向、网络中断重试、保存后重新打开、顾客菜单及历史订单读取。发布前更新微信后台隐私保护指引中的照片/相机能力说明。Sharp本机转码与SDK签名测试不能证明云端写入成功；Linux容器构建仍须在云端验收。

## 个人信息与账号申请

会员页及规则页提供独立“个人信息与账号”入口；会员退出仍仅处理会员权益。

- 顾客可修改昵称和资料手机号，或确认清除昵称、头像、资料手机号。不会改写已提交订单中的收货信息，也不清零积分红包。
- “清除本机收货资料”移除当前设备保存的联系人、手机号、地址和未提交结算缓存；通知已有首页内存清除旧资料，防止切回后重新带出。其他设备、历史订单和本地开发身份不受此操作影响。
- 个人信息处理申请支持查阅副本、更正、删除和申请注销。008迁移新增独立申请表。一个顾客仅有一笔处理中申请；相同请求号和内容可安全重试，换内容拒绝；未接单可撤回，已接单须联系掌柜协商。
- 掌柜在“信息申请”队列接单并记录具体回复，工作台可见待处理数量。管理写入和审计同一事务；已回复内容不能覆盖。界面固定显示“已回复”，不会将提交或回复显示成“已注销”。
- 回复是处理记录，不自动执行账户关闭、批量匿名化或交易资料删除。经营者须落实实际处理后说明完成范围；暂不能完成时如实说明原因和后续安排，不能只改状态宣称已删除。正式营业前仍需经营者确定资料保留依据及期限、备份中信息的处理办法，以及有进行中订单/退款/售后和未用权益时的注销实施方案。本轮没有验证完整账号注销。
- 实际处理前核对请求人微信身份和本人申请范围；禁止以申请中的自由文本直接执行SQL或更改他人资料，不要求顾客在申请中提交密码、验证码或密钥。需提供副本时应通过本人可访问的受控渠道交付，回复中不能包含密钥或他人信息。

验收需覆盖：顾客只能查看与撤回自己的申请；普通顾客不能访问掌柜队列；重复及并发提交不重复建单；接单后不能直接撤回、回复不能覆盖、审计失败整笔回滚；回复注销申请不改变交易或资产；清除本机资料后首页没有旧联系人和地址；离开页面丢弃迟到响应。小程序微信后台隐私指引应与真实收集字段、用途及联系方式保持一致，文案更新不能代替经营者的实际资料处理。

## 经营日报与核对口径

掌柜从工作台进入“经营日报”，按北京时间选择日期。009迁移新增顾客实付、实退字段和入账查询索引，须与新后端一并部署。

- 支付按服务端确认成功的 `pay_time` 入账，退款按服务端确认成功的 `closed_time` 入账，均包含当日00:00、不包含次日00:00。通知延迟可能导致入账日与微信交易发生日不同；当前不按微信账单日期回溯。
- 支付笔数包含零元单，也包含后来退款中的订单；退款仅在确认成功后单列，跨日退款扣在退款入账日。重复通知不改动原入账时间或金额。当前只支持整单退款。
- 订单支付金额为扣门店积分红包后、含配送费的应付，可能含微信渠道优惠。另行展示可信支付结果中的顾客实付和可信退款结果中的顾客实退；两者均不是商户结算净到账或利润。
- 旧正金额记录不回填猜测值；经确认的零元支付/退款可回填0。所选日期实付/实退存在缺失时，仅显示已记录部分与缺失笔数，不计算完整现金差额。全库LEGACY及缺入账时间记录另行提示，未猜测分配到某天；需对照真实商户记录核对。
- 单次汇总使用数据库只读一致快照，避免并发退款造成同一份汇总中先后查询矛盾。支付/退款明细另行分页读取，可能比汇总更新，应刷新后核对；点击单号可复制到工作台搜索。接口仅掌柜可见，不输出收货资料或OpenID。
- 预约日订单进度是本次读取时的状态。菜品按该预约日有效PAID订单汇总，剔除退款中、已退款、未付款和LEGACY；金额为成交单价小计，未扣积分红包、不含配送费，页面只展示份数前30项并提示其他项目。它不代表该日现金营收或已出餐成本。
- 积分红包按账户流水发生日分账户、事件汇总，保留正负方向和单位；待抵回与可用余额分别列示，不算现金收入。尚无手续费、原料/包装/配送成本、备货损耗或利润报表。

上线验收需用真实订单核对微信优惠后的实付、跨日退款、零元支付、重复通知、历史缺失提示、明细分页和普通顾客访问拒绝；本地数据库与接口替身通过不能替代微信账单核对。

## 营业设置与自提地址维护

掌柜可在“设置”中维护门店详细地址、联系人姓名、电话和付款时限，并选择免费、消费晋级或掌柜邀请模式。消费门槛支持精确输入68元等金额；推荐返利和红包抵扣比例可设为0。地址应包含完整街道门牌，经营者须核对真实性。

后台从管理员专用 `GET /api/admin/config` 读取完整配置与版本指纹。读取失败不开放表单保存；读取和保存期间禁止继续编辑，重复点击不重复提交。下拉或点击重新读取时，如有未保存填写须先明确确认，失败与冲突保留填写，离开页面忽略迟到响应。

保存 `POST /api/admin/config/update` 须携带读取时的 `expected_revision`。服务端在同一事务锁定配置记录，核对指纹及合并后的截单/出炉关系，再保存及记录审计；不同内容的旧版本请求返回409，不能覆盖其他设备已保存的设置。相同内容重试可确认当前结果，不重复改写配置。该接口需与新小程序同时升级，旧版不带指纹的保存会被拒绝；不新增迁移。

首页结算、会员页和规则页提供复制当前门店自提地址。订单详情复制的是该订单保存的取餐地址，地址改动不回写历史订单。搬址时掌柜须主动联系受影响顾客协商安排，不能仅修改设置后假定历史订单同步改变。复制只写剪贴板，不读取剪贴板或申请定位；失败不显示成功。

本地已验证冲突并发仅一笔可保存、相同内容重试、缺指纹及顾客访问拒绝、审计故障回滚，以及新旧自提订单地址快照。真机仍需核对完整表单、小屏与键盘、重新读取确认、地址复制及剪贴板反馈，不能用编译通过替代界面验收。

## 门店准备

- 掌柜配置真实的本批可售份数，核对实拍、菜品价格、净重规格、辣度、保存食用说明和必要的过敏原提示。每批默认份数只影响尚未开始预订的批次，已存在批次使用“本批剩余份数”调整。
- 在掌柜设置中配置每批接单上限 `BATCH_MAX_ORDERS`，初始0表示不限；工作台显示本批已接数（含待付款、已完成）和剩余名额。下单失败不占名额，未付款取消或备餐前退款成功后释放；已备好或发出的餐品退款不释放已使用的厨房接单容量。该配置按订单笔数限制，菜品份数仍由库存控制。
- 配送白名单为空时只支持自提；填写实际可送小区后才能自送。基于小区名称的服务范围校验不是精确测距，门牌完整性仍需掌柜确认。
- 每天检查全部日期待办和往日未取餐；联系顾客后凭自提码交付，配送核实送达需填写说明。工作台每15秒检查仅在页面打开期间有效，离线时需门店另行关注订单。
- 核对联系人、电话、门店信息、出炉/截单/可预约天数、休息开关、免配送门槛、会员与返利规则。
- 资质信息沿用项目提供资料，正式发布时由经营者核对有效性及展示材料。小程序隐私声明和地址能力授权须在微信管理后台与实际收集信息一致。
- 顾客可从订单提交售后并查看进度，掌柜在后台售后队列接单及回复；回复不会改变资金状态。开始配送、备好自提或完成后，可由掌柜填写原因，确认整单售后退款；部分退款尚未支持。已备好或发出的餐品退款后不自动恢复可售。已发积分和返利在渠道确认成功后冲回，余额不足部分单独记为待抵回，从后续同类奖励抵回，不扣现金；退会已清零红包不重复扣回。

## 微信真机与真实资金验收（待执行）

- 在用户已授权的现有环境中，以可辨认的联调订单完成最小金额成功支付，核对商户后台订单号、金额、用户和交易号；不能通过客户端直接更新付款状态。真实支付由用户在微信中完成。
- 用户取消支付、支付成功但通知延迟、客户端断网后退出重进、连续点击结算、重复通知，订单与资产最终一致。
- “我的订单”以列表返回的服务端时钟展示近似付款倒计时，手机时区不改变北京时间截止；到点不由客户端取消订单或返还积分，保留查询支付结果。进入后台后停止刷新并忽略迟到响应，返回后恢复一次刷新；多页历史不被静默轮询收起，重复取消确认不多次提交。
- 模拟通知金额、商户、AppID、买家、签名错误，均不得入账。未知验签密钥必须失败并告警，配置轮换后旧新密钥可按对应ID校验。
- 在商品库存充足时同时争抢最后一个批次名额，最多一单成功；失败或重复提交不多占名额，取消释放，已备好后售后退款不重新开放名额。已有订单不因调低上限而被取消。
- 同时购买最后一份，最多一单成功；未付款超时与手动取消后库存及积分只返还一次。
- 支付成功与关单同时发生，以微信可信结果核对；已取消订单迟到支付必须进入退款补偿队列，不能静默丢弃。
- 待备餐已付款订单退款，核对微信渠道退款成功、资金到账、积分返还、消费额回退；退款超时或异常不得显示已退款。
- 对已备好、配送中、已完成订单由掌柜申请整单退款，核对原因留痕、重复请求不重复处理、已消耗库存不恢复；已用奖励待抵回可查，后续同类奖励先抵回，已随退会清零部分不再重复扣回。
- 今日/明日、自送/自提订单混合，今日发车只改变选定批次自送订单；自提备好后凭正确码核销一次。
- 掌柜核实送达前需联系顾客并填写确认说明；缺少明确确认或说明时不得完成，重复操作不重复发奖，保存操作人和原始凭据；审计失败需连同履约变更回滚。
- 工作台打开期间每15秒检查全部日期待办；首次打开不弹历史新单，重复支付/售后不重复提示。切后台停止检查，回前台继续，断网明确提示数量可能过期。点击往日未取餐只显示历史待取订单并可联系顾客，不自动核销或发奖；全部日期视图无单批发车、汇总或容量。此功能不提供离线推送。
- 售后只能查看和提交本人的订单问题，重复提交不重复建单；掌柜接单及回复可见，回复不改变资金状态，不能覆盖已回复的处理结果。
